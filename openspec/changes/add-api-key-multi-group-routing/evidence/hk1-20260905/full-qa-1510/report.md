### 确认的差异

- 管理按钮使用独立 `AccountTestService`，不经过用户Key的路由/计费链路；非OAuth API Key探测也调用 `applyOpenAICodexProbeHeaders`。
- 该函数补 `User-Agent`、`originator`、`version`、`OpenAI-Beta`、`X-Codex-Window-ID` 等Codex身份/探测头。
- 普通API Key转发主要透传请求头白名单；Codex协议账号的强制身份处理不等同于所有OpenAI API Key账户都会自动补齐同一组头。脚本的普通HTTP调用与管理探测不是等价客户端请求。
- 请求体也有差异：首个脚本是短输入/none reasoning/32输出上限；第8次已经对齐hi和instructions并去掉reasoning，仍失败，但保留了输出上限，因此并非完全单变量实验。

**已经排除“该账号的gpt-5.6-sol完全不可用”；尚未证明具体403就是客户端身份限制。** 请求头/客户端识别是当前首要怀疑点，还需确认供应商允许的客户端契约或取得相应拒绝原因。未伪装额外身份头绕过上游限制，未擅自修改正式转发逻辑、上游配置或部署。
