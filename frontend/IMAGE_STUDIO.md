# 图片创作

用户通过侧边栏「图片创作」进入 `/image-studio`。页面采用上方批次历史、底部输入区的结构，同时适配浅色、深色和移动端。

模型、Key／分组选择使用全局 `Select`；比例、分辨率、张数与宽高合并在一个紧凑面板中，复用全局 `Select` 弹层和 `Input`，支持键盘 Escape、点击外部关闭、深色和窄屏布局。提示词和 Key 名称使用全局 `TextArea`／`Input`。参考图默认堆叠，桌面悬停或键盘聚焦后展开，可逐张删除及继续添加；触屏可点击展开。删除后保留可继续操作的焦点，Escape 收起。

## 渠道与密钥

- 从 `GET /api/v1/groups/image-generation` 获取当前用户可以绑定的分组，只允许 `platform=openai`、`status=active`、`allow_image_generation=true`，且分组账户支持至少一个 GPT Image 模型（遵循账户模型映射及分组模型列表）。无账户和纯文本分组不展示。
- 分页读取 `GET /api/v1/keys`，排除停用、过期和额度耗尽的密钥，只展示 OpenAI 生图 Key。
- Key 下拉包含「新建生图 Key」入口，点击后才打开弹窗；分组下拉仅展示上述生图分组。通过 `POST /api/v1/keys` 创建后自动选中。
- Key 下拉仅匹配生图能力接口返回的分组，模型选择共用其 `image_models`。无需已有 Key 即可筛选新建分组；发现能力不受 Key 的余额拦截，也不会发起计费请求。加载失败时保留重试入口并禁止创建、生成。

## 生成与结果

- 文生图调用 `POST /v1/images/studio/generations`；有参考图时以 multipart 调用 `POST /v1/images/studio/edits`，参考图字段为 `image[]`。提交沿用网关的 API Key 鉴权和计费；通过登录账号的 `GET /api/v1/image-studio/history/:id` 查询任务与结果，不再依赖提交时的 Key。
- 支持提示词、1–4 张输出，以及 1:1、16:9、9:16、4:3、3:4、3:2、2:3、21:9 比例。GPT Image 2 按比例提供 1K／2K／4K 三档预设，默认 1K，宽高输入框和悬停提示显示实际像素；方形默认 1024×1024，16:9 默认 1792×1008，9:16 默认 1008×1792。全部尺寸见 [预设核对表](IMAGE_STUDIO_SIZE_AUDIT.md)。分辨率展示与按最长边计算的计费档位分开，尺寸遵循 [OpenAI 约束](https://developers.openai.com/api/docs/guides/image-generation#size-and-quality-options)。旧版 GPT Image 使用标准尺寸及 1:1／3:2／2:3 比例。4:5／5:4 历史记录仍可展示，但不再提供为新选项。
- 比例菜单移除自动选项，默认选中 1:1。已有自动比例历史仍按原始元数据展示；重新编辑时回到 1:1，提示比例不可用，由用户确认后提交，不自动生成不同于原记录的比例。
- 固定比例可手动修改宽高，按比例联动并对齐 16 像素；不合法尺寸禁止提交。任务元数据保存实际请求尺寸 `size`，刷新和重新编辑可恢复自定义尺寸，旧记录兼容原有预设。
- 提交任务后立即清空提示词和参考图，保留 Key、模型与参数；历史记录保留原提示词和参考文件，失败时也可重新编辑。请求完成不会覆盖后来输入的新草稿。
- 历史记录复用输入区的参考图组件，以紧凑堆叠展示全部参考图，悬停、聚焦或触屏点击展开查看；历史区不显示添加、删除按钮，无参考图时不显示占位图标。
- 参考图最多 4 张，每张最多 10 MB，支持 PNG、JPEG、WebP。生成图片的悬浮操作区和预览弹窗均提供「作为参考图」，触屏直接显示入口；读取最新图片链接并追加到当前参考图，保留现有提示词和参考图，防止重复添加及超出上限。
- 参考图和生成结果存入对象存储，数据库仅保存稳定文件 ID、存储配置 ID、对象路径及文件校验信息。预览和下载链接按需生成，不将 base64 或签名 URL 写入历史。支持重新编辑、再次生成及删除账号下的历史记录。
- 支持同时提交多个生成任务，各自保存输入快照、轮询和结果；单次提交不自动重试计费 POST，短暂轮询失败可重试 GET。已知任务 ID 的连接中断可点「继续查询」，不会重新生成。
- 服务端在调用上游前创建数据库任务，收到任务 ID 后开始查询；刷新、换浏览器或撤销原 Key 后，仍能通过登录账号读取历史。没有收到任务 ID 的请求不自动重发，可刷新历史确认。进程重启不会自动重试计费请求，超过 35 分钟仍未完成的任务显示中断。
- `GET /api/v1/image-studio/status` 只暴露可用状态；未启用对象存储时禁止提交。存储中途失效则报告保存失败，不会回退把 base64 写入 Redis。

## 历史与价格

历史保存在 PostgreSQL，按登录用户隔离，每页 20 条并支持继续加载。页面按旧到新展示，进入页面后滚动至底部；向前加载时保留阅读位置，新提交任务追加到下方。保存提示词、模型、比例、分辨率、张数、Key 名称和 ID、状态、时间，以及参考图和结果的文件 ID，**不保存 API Key 密文或明文**。切换账号会清空内存中的作品并中断旧请求。访问、删除历史及刷新文件链接均校验归属；删除使用全局危险操作确认弹窗；用户确认后清理生成图、参考图及已登记的迁移副本，再从数据库彻底删除历史及文件记录。对象删除失败时保留数据库记录供重试；重试允许对象已不存在。迁移与删除锁定同一条创作记录，避免迁移期间产生遗漏副本。

旧 IndexedDB 记录在当前用户进入页面时自动导入：旧任务先查询服务端恢复有效链接，再上传原图与参考图到当前生图存储；服务端按用户及旧记录 ID 幂等导入，最多 20 条。导入成功后才移除对应的本地记录，失败时保留并提供重试，不会再次调用模型。没有可读取原图的旧记录不能凭过期 URL 恢复图片内容。页面底部不再显示浏览器保存说明。

## 生图存储设置

管理员统一在「设置 → 数据备份 → 异步生图对象存储」配置 S3 兼容存储，图片创作与已有异步生图接口共用开关、Bucket、路径和凭证，也支持复用数据库备份的 S3 凭证。已移除重复的「生图存储」标签及独立配置接口。服务端保留不可编辑的配置快照用于历史文件定位，凭证使用固定 TOTP 密钥加密，管理接口不返回 Secret Access Key。

- 每次提交读取共享设置，变更后自动保存配置快照，重复保存及启停共用同一快照。新任务使用新配置；正在执行的任务继续使用提交时的配置，旧文件继续按各自的原配置访问。
- `GET /api/v1/image-studio/files/:id` 按稳定 ID 生成新的下载链接。历史不会因签名过期、域名或当前存储切换而丢失。
- 将历史图片迁移到当前存储时，服务端分批复制参考图和输出图，读取源文件及目标文件进行 SHA-256 校验，再更新文件位置。ID、历史内容和创建时间不变；失败时保持原位置，原文件不会删除。迁移完成前须保持原存储及凭证可用。
- 设置继续使用 `/api/v1/admin/backups/image-storage`；历史位置与迁移接口为其下的 `/history` 和 `/migrate`。有旧文件时，在同一设置卡片中显示可展开的「历史图片存储」，可迁移到当前配置。设置保存及迁移使用已有管理员二次验证。

价格按当前尺寸档的分组单价及图片倍率（或用户分组倍率）计算，统一显示 `$金额 / 张`，不再显示预计总价或参考价提示；切换张数不改变单价，切换 Key 或尺寸后更新。高峰倍率开启、缺少明确分组价格或无法获取用户倍率时显示「按实际用量计费」。本次调整价格展示，最终费用仍由现有网关计费逻辑决定。

## 验证

在 `frontend` 目录使用兼容原锁文件的 pnpm 10：

```sh
corepack pnpm@10.17.1 install --frozen-lockfile
corepack pnpm@10.17.1 build
corepack pnpm@10.17.1 exec vitest run src/api/__tests__/imageStudio.spec.ts src/stores/__tests__/imageStudio.spec.ts src/views/user/__tests__/ImageStudioView.spec.ts
```

功能测试覆盖分组／密钥过滤、分页、创建后自动选择、请求参数、参考图 multipart、禁止重复提交、历史恢复及账号隔离。浏览器验证使用模拟响应，不会调用真实付费模型。

## 本地对象存储验证

本 worktree 的开发环境使用独立 MinIO 容器 `sub2api-image-studio-minio`，S3 端点 `http://127.0.0.1:9182`、私有桶 `image-studio`，数据与凭证留在忽略提交的 `.dev/` 目录。后台「数据备份 → 异步生图对象存储」统一配置，无需修改正式环境。

`TestImageStudioAsyncStoresAndDownloadsFromS3` 是可选的集成测试，通过 `IMAGE_STUDIO_TEST_S3_ENDPOINT`、`IMAGE_STUDIO_TEST_S3_BUCKET`、`IMAGE_STUDIO_TEST_S3_ACCESS_KEY`、`IMAGE_STUDIO_TEST_S3_SECRET` 注入本地存储。它使用固定 PNG 模拟上游，验证异步任务上传、去除 base64、返回签名链接以及下载字节，不调用真实模型。

`TestImageStudioDatabaseHistoryAndStorageMigration` 另外使用 `IMAGE_STUDIO_TEST_DATABASE_URL` 连接 PostgreSQL，在临时 schema 中验证迁移幂等、账号隔离、历史分页、服务重建后的持久化、固定存储配置、凭证加密、稳定文件 ID、签名下载、复制校验和迁移失败恢复，测试结束后清理 schema。数据和图片均为固定测试素材，不调用真实模型。
